# Instructions for the weekly update

This repo is a list of Python asyncio libraries. `libraries.yml` is the source of truth. `README.md`, `news/`, `feed.xml` and `data/` are generated by `tools/update.py`. Never edit them by hand.

Commits use conventional commits (`feat:`, `fix:`, `docs:`, `chore:`). Do not write a changelog.

## Two ways to run the update

Both follow the rules below.

- **GitHub Actions, every Monday** (`.github/workflows/weekly.yml`). `tools/classify.py` finds candidates and asks the Mistral API for a category and description. It needs the `MISTRAL_API_KEY` secret. Then `tools/update.py` refreshes the data. No Anthropic key is used.
- **Locally with Claude Code.** Follow the steps in "Running it locally" yourself, instead of calling Mistral.

## Selection rules

- A candidate is a Python repo whose name starts with `aio` or `async` (`asyncio` included) and that has at least 20 stars. `tools/discover.py` applies this filter. Libraries that do not follow the naming but are clearly asyncio libraries can be added by hand.
- Keep it only if it is a library or framework for asyncio. Skip tutorials, awesome lists, applications, examples, forks and anything that only has the prefix in its name.
- Archived repos are fine. The script marks their status.
- Pick exactly one category id from `categories` in `libraries.yml`. If none fits, skip the repo.
- The description is one factual sentence in English, at most 110 characters, with no trailing period. Say what the library does. No marketing words (powerful, blazing, modern, seamless, robust) and no em or en dashes.

## Entry format

```yaml
- name: example
  repo: owner/example
  pypi: example            # omit if the PyPI project does not point back at the repo
  category: http-clients   # an id from `categories`
  description: Async client for the Example API
  added: 2026-10-05        # today's date, always set for new entries
```

## Running it locally

1. Run `uv run tools/discover.py > /tmp/candidates.yml`. It lists repos not yet in `libraries.yml`, best starred first. Candidates you already rejected are in `data/rejected.json`; skip them.
2. Apply the selection rules to the first 40 or so. Append the accepted ones to `libraries.yml` in the entry format. Add the rest to `data/rejected.json` so they are not reviewed again.
3. Check PyPI names with `curl -s https://pypi.org/pypi/<name>/json` and keep `pypi` only when the metadata links to the repo.
4. Run `uv run --with pytest --with httpx --with pyyaml pytest -q`, then `uv run tools/update.py`. Look at the `no_pypi` and `stale` lists it prints. Fix wrong names and remove repos that no longer exist.
5. Commit with explicit paths: `libraries.yml`, `data/`, `README.md`, `news/`, `feed.xml`. Message: `feat: add <n> libraries` or `chore: weekly update`.
